# Инструкция для ИИ-агента, который продолжает этот проект

## Что это и зачем

ИнваРадар Pro — слой исполнения поверх карты InvaRadar. Код и документы этого слоя лежат в каталоге `pro/` репозитория InvaRadar. Цикл: сигнал → закон в наряде → подпись человека → доказательство работ → контроль пяти сезонов → закрытие. Плюс аудит коридоров для обладателей сервитутов.

Цель команды — попасть в топ-10 демо-дня 11-го потока «Академии инноваторов». Подача — до 22.01.2027, официальный срок — 25.01.2027.

Сначала прочитай документы в таком порядке:
1. `docs/00_SUT_I_SMYSL.md`;
2. `docs/01_AUDIT.md`;
3. `docs/07_TOP10_PLAN.md`.

## Инварианты — не нарушать

1. **Нормы.** Нельзя ослаблять запреты в `rules/*.yaml` без ссылки на норму и без нового теста. Любая правка правил прогоняется через `tests/test_events_law.py::test_invariants_on_random_contexts` и `make consistency`.
2. **Отказ в безопасную сторону.** Если слой неизвестен, пестициды и беспилотник запрещены. Не меняй это поведение.
3. **Подписи только человека.** `order_approved`, `legal_cleared`, `work_accepted`, `work_rejected` и `case_closed` выполняет только `kind: human`. Не добавляй обходов ни в API, ни в инструменты агента.
4. **Разделение обязанностей.** Работу принимает не тот, кто её сдал. Метод работ должен входить в `decision.allowed` на каждом шаге.
5. **Журнал.** Только добавление. Не правь `events.jsonl` руками и не меняй формат хеша без миграции и теста на обнаружение подделки.
6. **Сверка фактов.** Не выдумывай правовые факты. Новая норма без проверки по официальному тексту получает `verified: false`. Такие нормы не создают обязанностей.
7. **Честные метрики.** Не называй ранжирование «прогнозом», пока не сделан ретро-прогноз на эмбеддинге прошлого года (аудит A-02). Не подавай синтетику демо как результат пилота.
8. **Закрытие очага.** Не ослабляй правило «максимум из двух»: нормативный минимум 3/5 сезонов и P(жив) ≤ `closure.p_max`. Параметры закрытия меняются только с обоснованием по полевым данным.
9. **Хеширование Меркла.** Не меняй префиксы 0x00/0x01 и разбиение по RFC 9162: проверки третьих сторон сломаются.
10. **Формальная проверка.** Любое изменение `rules/*.yaml` — только после `make lawcheck`: все свойства должны быть ok.
11. **Пороги хешей.** Меняются только по бенчмарку на реальных снимках (`analysis/evidence_bench.py`), с учётом множественных сравнений.
12. **Персональные данные.** Храни только SHA-256 исходников и копии без метаданных. Не отправляй персональные данные в зарубежные сервисы и модели.

## Как добавить

- **Норму.** Правило в `rules/federal.yaml`: `when`, `prohibit` или `require`, `cite` с `verified`. Затем тест в `test_events_law.py` и `make consistency`.
- **Юрисдикцию.** Файл `rules/<pack>.yaml` с `lists` и `verified`. Пока не сверено — `verified: false`.
- **Вид.** Раздел `taxa.<вид>` в `rules/methods.yaml`: план по размерам, `always`, `followup`, `min_clean_seasons`.
- **Событие.** Записи в `ROLES`, `SOURCES` и `_guard` в `workflow.py`, обработка в `apply`, тест на запрет и на разрешение.

## Ближайшие задачи (по ценности для топ-10)

1. **Ретро-прогноз без утечки.** В репозитории InvaRadar пересчитать вариант с `embedding_year` 2024 и сравнить долю новых мест 2025–2026 годов в верхних 20% площади (A-02). Оценивать строго по протоколу `docs/11_PREREGISTRATION.md` и функциями `validation.capture_report` и `retro_forecast_verdict`.
2. **Бот для жителей.** Telegram или MAX: фото → классификатор InvaRadar (`outputs/photo/verifier.joblib`) → `signal_received` и `field_result` с `verified_by: ai_photo` (`docs/02_PRD.md`, F14).
3. **Веб-интерфейс.** Карта, очередь, паспорт, подпись наряда (F16).
4. **Приложение подрядчика.** Время и место от сервера, код наряда в кадре (F15).
5. **Хранилище.** PostgreSQL только на вставку, снимки состояния, вход через OIDC (`docs/03_ARCHITECTURE.md`).
6. **Пакет Московской области.** Сверить акт и включить `verified: true` только после сверки.
7. **Маршруты по дорожному графу** вместо прямой (аудит M-03).
